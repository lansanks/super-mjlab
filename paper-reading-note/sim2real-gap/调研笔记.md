# 四足 Sim2Real Gap：方法地图与落地路线

> 调研时间：2026-11 · 范围以四足 locomotion 为主，兼顾可直接迁移的人形/机械臂方法
> 关联：本仓库 `mjlab` 的执行器/延迟/DR 接口（见 §6）

---

## 0. 结论先行

1. **gap 的主体不是刚体参数，而是执行器 + 时序。** Hwangbo 2019 的对照实验很说明问题：理想执行器模型预测力矩的 RMS 误差 3.55 N·m，学习到的执行器网络 0.74 N·m；在真实策略数据上分别是 5.74 / 0.97 N·m。刚体惯量再怎么随机化，也补不上这个量级的力矩误差。
2. **"能测的建模、测不准的随机化"是当前最稳的配方。** 执行器/延迟/质量这类**每次部署都一样**的东西，用辨识或学习模型做准；摩擦、地形、负载、传感器噪声这类**每次都不一样**的，用域随机化 + 在线自适应兜住。
3. **执行器建模的性价比最高。** Tan 2018（Minitaur）、Hwangbo 2019（ANYmal）、Lee 2020、Rudin 2021、Miki 2022 这条 ETH/Google 线，核心都是"把电机 + 减速器 + 内部控制器 + 通信延迟"整体当成一个黑盒学出来，而不是去拟合一堆物理参数。
4. **2024 年后出现第三条路：不改策略，改仿真器（Real2Sim）或用真机数据反推仿真参数**，5 分钟真机数据就能显著降漂移；以及反向的"把真机整形成仿真里的理想模型"（actuator reality shaping）。
5. **没有银弹。** 单一方法都有明确失效模式：DR 补不了固定延迟，执行器模型补不了接触随机性，在线自适应补不了不可观测的灾难状态。工程上通常是 3 件套组合。

## 1. 先把 gap 拆开：7 个可测量项

| # | 来源 | 具体量 | 怎么测（真机） | 对应手段 |
|---|---|---|---|---|
| 1 | 本体惯性 | 连杆质量/质心/惯量、**转子反射惯量**（armature） | 称重 + CAD + 单摆/自由落体辨识 | 显式建模 + 小幅 DR（±5–15%） |
| 2 | 关节摩擦 | 库仑摩擦、粘滞阻尼、齿隙、传动柔度 | 等速正反转、正弦扫频、力矩-速度曲线 | `frictionloss` / `viscous_damping` / LuGre + DR |
| 3 | 电机 | 力矩常数、电流/电压限幅、反电动势、磁饱和、温漂 | 堵转 + 负载台架，画力矩-速度包络 | DC 电机模型 / 执行器网络 / 解析模型 |
| 4 | 控制时序 | 通信延迟、控制周期、内部 PD 环路、采样保持 | 阶跃响应打时间戳、互相关 | 显式 `delay` + decimation |
| 5 | 接触 | 地面摩擦、软硬、接触模型参数 | 拖拽测力、落地冲击 | 摩擦 DR + `solref/solimp` 标定 |
| 6 | 传感器 | IMU 噪声/零偏、编码器量化、外感知噪声与遮挡 | 静置 Allan 方差、与 mocap 对比 | 观测噪声 + 观测延迟 + 历史编码 |
| 7 | 状态估计 | 基座线速度不可直接测、姿态漂移 | 与 mocap 对比 | 训练时用特权信息蒸馏 / 估计器在环 |

**诊断阶梯**（判断哪一项主导，按顺序做）：

1. 机器人吊起来，给单关节正弦指令 → 跟踪误差大 = 执行器/延迟（#2 #3 #4）
2. 原地踏步，看基座漂移 → 接触/腿部质量（#1 #5）
3. 直线行走看 yaw 漂移 → 左右不对称、装配误差（#1 #2）
4. 高速奔跑看打滑/饱和 → 力矩-速度边界（#3）
5. 静置采 IMU → 噪声/零偏是否与训练一致（#6）

## 3. 逐族详解

### 3.1 执行器 / 电机建模（最高性价比）

三条路线：

**(a) 解析模型**：Tan et al. 2018（Minitaur）用系统辨识得到执行器模型，显式模拟通信延迟，再加动力学随机化与扰动。问题是对直驱电机可行，对减速器/SEA/液压就难。

**(b) 学习模型（actuator net）**：Hwangbo et al. 2019 的做法值得逐字看：

- 输入：**位置误差**（目标减实际）与**关节速度**的历史，取 `t, t-0.01s, t-0.02s` 三帧（6 维）
- 网络：MLP，3 隐层 × 32 单元，`softsign`（比 tanh 快 2.5 倍：12 关节 12.2 µs vs 31.6 µs）
- 数据：正弦足端轨迹（幅度 5–10 cm，频率 1–25 Hz）+ 人工扰动，**不到 4 分钟**、400 Hz、>100 万样本
- 精度：验证集 0.74 N·m RMS（力矩传感器分辨率 0.2 N·m），理想模型 3.55 N·m
- 关键洞察：**内部的电流环、减速器摩擦、通信延迟都被隐式吸收**，不需要分别建模

Lee et al. 2020 直接复用这个 6 维输入（`t, t-0.01, t-0.02` 的误差+速度）训练 SEA 模型；Rudin et al. 2021 把它简化成 **LSTM 只吃当前测量**，并报告了一个工程约束：执行器网络本身会限制物理步长，`dt` 不能小于 0.005 s（否则网络发散）。

**(c) 硬件整形（反向）**：Actuator Reality Shaping（2026）不去改仿真，而是给每个关节加 **2-DoF 前馈-反馈控制器（500 Hz）**，把真机的闭环响应整形成仿真里的二阶参考模型，于是策略零样本迁移、不需要学执行器模型。已在机械臂、轮腿、人形上验证（**注意：论文没有专门做四足**）。

**2025–2026 的细化方向**：

- 高速场景要显式建模**电压耦合与磁饱和**、力矩-速度包络，否则高速段 gap 明显（RA-L 2026, arXiv:2609.13289）
- 液压机器人用解析执行器模型，12 个执行器预测 <1 µs，可塞进 RL 循环（RA-L 2025, arXiv:2601.11143）
- 更激进：用 **PMSM 能量模型 + 极简参数集**，在 13 台机器人上做到"**完全不做动态参数随机化**"也能可靠迁移，CoT 还降了 32%（IJRR 2026, arXiv:2509.06342）

**什么时候够用**：如果你的机器人是"位置指令 + 内部 PD + 减速器"，且能采到几分钟激励数据，这条线几乎总能显著改善。

---

### 3.2 域随机化：用对，而不是用大

- 起源：Tobin 2017（视觉 DR）；Peng 2018 把 DR 用到动力学；OpenAI 2019 的 ADR 自动退火区间
- 自动化：BayRnTune（2023）贝叶斯 DR + 微调；DrEureka（RSS 2024）用 **LLM 直接生成奖励函数和 DR 分布**，在四足瑜伽球平衡上零人工调参
- 区间怎么定：Impedance Matching（2024）用频域分析确定 DR 区间，避免拍脑袋，支撑了 55 cm 跳远

**反例很重要**：Lee 2020 / Miki 2022 基本不做大规模动态随机化，靠执行器网络 + 特权蒸馏就上了野外；2509.06342 干脆报告"不做动态参数随机化"。说明 DR 不是必要条件，而是**在没有准确模型时的替代品**。

**实践原则**：

1. 只随机化"你真的不知道且会变"的量（摩擦、负载、地形、传感器噪声）
2. 区间要物理可信；过度随机化会训练出蹲着走、能耗高的保守步态
3. 延迟不要靠 DR 覆盖——它是**结构性**的，要显式建模
4. 观测噪声按实测统计量设（Rudin 2021 明确说噪声幅度来自真机测量）

---

### 3.3 特权学习 + 历史编码：把"测不到"变成"推得出"

- **Lee 2020**：教师策略看特权信息（地形、接触、摩擦），学生只看本体感知历史，监督蒸馏。部署时不需要任何辨识
- **Miki 2022**：把外感知也纳入，循环**信念编码器**融合本体 + 带噪高度采样；训练时用"干净高度 + 特权量"做重建损失，推理时视觉不可靠会自动退化到本体
- **RMA 2021**：基座策略 + 自适应模块，后者从 (观测, 动作) 历史回归环境隐向量（摩擦/负载/电机强度），部署时**在线**估计
- **DreamWaQ 2023**：CENet 用自监督（速度监督 + VAE 重建）学上下文隐变量，隐式"想象"地形
- **CARO 2026**：不建执行器模型、不用力矩传感器，用固定基座 Euler-Lagrange 模型构造**力矩残差观测** + 扰动观测器，零样本迁移

**本质**：这些都是"隐式系统辨识"——不显式估计参数，而是让网络从历史里推断"当前这个世界有多不一样"。所以**历史窗口长度**是关键超参，经验上要覆盖最长延迟 + 机械响应时间（Hwangbo 明确说过这个判据）。

---

### 3.4 在线自适应：部署时还在变的东西

RMA 之后这条线基本收敛成"context-aided"范式：策略输入里带一个从历史推断的 latent，训练时用特权信息监督它。

适用场景：负载变化、电池电压下降、电机发热、地面材质突变、磨损。

**代价**：latent 估计不准时会引入新的失败模式；训练时 latent 的监督信号质量决定上限。

**替代思路**：加传感器而不是加模型——足底 IMU（2025，arXiv:2504.00614）让策略直接"感觉"接触，绕开高减速比执行器建模难题。

---

### 3.5 Real2Sim / 系统辨识 / 可微仿真

- **经典 sysID**：Tan 2018、Hwangbo 2019（惯量 + 执行器）、2509.06342（自底向上：执行器 → 空中轨迹 → 地面行走）
- **主动激励设计**：IDTD（2026）用 Fisher 信息矩阵的 Schur 补设计激励轨迹，让不同参数"互不混淆"，参数辨识误差降 39.6%（Go2/G1/Crazyflie 仿真 + 真实 K1）
- **不用 mocap 的校准**：Proprioceptive Distribution Matching（2026）把真机与仿真的 rollout 当**分布**比较，不需要时间对齐和外部传感，**<5 分钟真机数据**就能显著降漂移（Go2，含两足行走）
- **可微仿真**：Song et al.（CoRL 2024）用"单刚体代理模型反传 + 非可微高保真仿真前向"绕开接触不连续，几分钟学会走，真机零样本；2404.02887（CoRL 2025）用可微接触模型，首次实现"完全在可微仿真里训练"的四足零样本迁移
- **Real2Sim 管线**：RSR 闭环（2025）、QuadVerse（2026，视觉+物理联合对齐）、GaussGym（2025，3DGS 渲染）

**判断**：可微仿真目前仍是"研究性强、工程性弱"，但 sample efficiency 优势明显；分布匹配这类"黑盒校准"最可能在工程里先落地。

---

### 3.6 真机数据闭环

- Smith et al. 2020：真机直接 RL，自动复位 + 最小人工，几小时学会走
- DayDreamer 2022：真机上训世界模型，样本效率比 model-free 高一个量级
- 功率微调（ICRA 2025）：仿真里没有的"整机功耗"用真机数据建模型再回灌仿真，总功耗降 24–28%
- Sim-real co-training：把真机数据混进训练（综述 2510.20808 归为独立一类）

**适用**：仿真里根本没有的目标（功耗、噪声、寿命），或最后 5% 的性能。

---

### 3.7 传感器与时序：最容易被低估

- **延迟要显式建模**：Tan 2018 就发现必须模拟 latency；Rudin 2021 观测噪声按实测设
- **观测延迟 ≠ 动作延迟**：两者要分别随机化/建模，mjlab 里是两套 buffer
- **状态估计在环**：Miki 部署时基座速度来自 IMU + 腿部运动学的估计器，训练时若用真值速度，部署必然掉点
- **外感知要按失效模式加噪**：Miki 的噪声模型是分工况的（正常 60% / 大偏移 30% / 大噪声 10%），不是随手高斯
- **编码器量化**通常不是主要矛盾，关节位置测量的**延迟与滤波**才是

## 5. 选型：成本 / 收益 / 证据

| 你的处境 | 首选 | 次选 | 别做 |
|---|---|---|---|
| 能上台架、有 1 小时 | 执行器网络（A） | DC 电机模型 + 延迟 | 大范围 DR 硬扛 |

## 6. 在 mjlab 里的映射

仓库已经具备大部分接口，基本不用改框架：

| 论文里的手段 | mjlab 对应 | 位置 |
|---|---|---|
| 位置伺服 kp/kv | `BuiltinPositionActuatorCfg(stiffness, damping, effort_limit, armature)` | `src/mjlab/actuator/builtin_actuator.py` |
| 力矩-速度 / 反电动势 / 电压限幅 / 磁饱和近似 | `BuiltinDcMotorActuatorCfg(motor_params, voltage_limit, inductance, thermal, lugre, cogging)` | 同上 |
| 学习执行器网络（Hwangbo 式） | `LearnedMlpActuatorCfg(network_file, history_length=3, pos_scale, vel_scale, torque_scale)` | `src/mjlab/actuator/learned_actuator.py` |
| 指令延迟 | `ActuatorCfg(delay_min_lag, delay_max_lag, delay_hold_prob)`（单位：物理步） | `src/mjlab/actuator/actuator.py` |
| 观测噪声 / 延迟 / 历史 | `ObservationTermCfg(noise, delay_min_lag, delay_max_lag, history_length)` | `src/mjlab/managers/observation_manager.py` |
| 摩擦 / 质量 / 惯量 / 质心 DR | `EventTermCfg(mode="reset"/"interval", func=dr.geom_friction / dr.body_mass / dr.pseudo_inertia, ...)` | `docs/source/randomization.rst` |

示意配置（数值只是占位，按实测替换）：

```python
from mjlab.actuator import BuiltinPositionActuatorCfg
from mjlab.envs.mdp import dr
from mjlab.managers.event_manager import EventTermCfg
from mjlab.managers.scene_entity_config import SceneEntityCfg

# 1) 执行器：显式转子惯量 + 干摩擦 + 指令延迟
LEG_ACTUATOR = BuiltinPositionActuatorCfg(
    target_names_expr=(".*_hip_joint", ".*_thigh_joint", ".*_calf_joint"),
    stiffness=30.0,
    damping=0.8,
    effort_limit=24.0,
    armature=0.01,          # 实测/手册的反射惯量
    frictionloss=0.15,      # N·m
    delay_min_lag=1,        # 物理步；1 kHz 下 1 step = 1 ms
    delay_max_lag=3,
)

# 2) 只随机化"会变且测不准"的量
FOOT_FRICTION = EventTermCfg(
    mode="reset",
    func=dr.geom_friction,
    params={
        "asset_cfg": SceneEntityCfg("robot", geom_names=[".*_foot.*"]),
        "ranges": (0.4, 1.2),
        "operation": "abs",
    },
)
```

**注意**：`delay_*_lag` 的单位是**物理步**，不是毫秒——按仿真步长换算，别按控制频率。这是最容易搞错的一处。

## 7. 四阶段路线图

**阶段 0 · 基线（1 天）**
在仿真里跑通，做一个 sim2sim（MuJoCo ↔ Isaac）对照。2512.18938 报告过两者接触模型差异会改变策略行为，这一步能提前暴露"仿真器依赖"。

**阶段 1 · 执行器辨识（2–3 天，收益最大）**
- 吊起机器人，单关节扫频（1–25 Hz，幅度覆盖工作空间）+ 阶跃
- 测：跟踪误差 vs 频率、阶跃上升时间/延迟、力矩-速度包络、静摩擦
- 拟合：kp/kv、`armature`、`frictionloss`、延迟（步数）
- 验收：同一指令下 sim 与 real 的关节轨迹在 50 ms 内误差 < 0.05 rad

**阶段 2 · 训练侧补齐（1 周）**
- 观测：按实测统计量加噪声；`delay` 显式建模；历史窗口 ≥ 延迟 + 机械响应时间
- 特权训练：critic 看真值（摩擦、负载、接触），actor 看历史（asymmetric actor-critic）
- DR 只覆盖摩擦/负载/地形，区间物理可信

**阶段 3 · 实机迭代（持续）**
- 记录真机日志，回放同一段指令到仿真，做**开环回放对比**——这是最有效的单一诊断
- 漂移大 → 回到阶段 1；抖动大 → 查延迟/噪声；打滑 → 查摩擦/力矩上限
- 仍不够再上：RMA 式自适应模块、执行器网络、分布匹配校准

**建议的验收指标**（工程经验值，非论文指标）：

| 指标 | 目标 |
|---|---|
| 开环回放 50 ms 关节角误差 | < 0.05 rad |
| 执行器力矩预测 RMS | < 0.5 N·m |
| 同指令基座速度误差 | < 0.1 m/s |
| 阶跃响应延迟差 | < 10 ms |
| 平地 CoT 相对差 | < 15% |

## 8. 常见坑

1. **延迟单位搞错**：物理步 vs 控制步 vs 毫秒，差一个 decimation 就是 4–5 倍的错误
2. **训练用真值速度，部署用估计速度**：这是最隐蔽的掉点原因
3. **DR 过大**：策略变保守，步态变蹲，能耗变差，且仍然过不了固定延迟
4. **只随机化刚体参数**：对执行器误差几乎无效（见 §0 的数字）
5. **观测噪声用高斯拍脑袋**：真机 IMU 的噪声是有色噪声 + 零偏漂移，统计量要对
6. **忽略接触模型**：`solref/solimp` 和摩擦锥参数会显著改变步态，sim2sim 就能看出来
7. **执行器网络过拟合激励数据**：Hwangbo 报告测试集误差（0.97）明显高于验证集（0.74），激励要覆盖真实策略的频段
8. **忘了电机温漂/电压下降**：长时间跑之后力矩能力下降，短时测试看不出来
