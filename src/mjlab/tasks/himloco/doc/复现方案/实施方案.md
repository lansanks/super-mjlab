## 1. 一句话概括

**HIM 与 DreamWaQ 在本仓库里的接口是同构的**——都是"45 维 o_t + v̂(3) + 16 维隐变量 →
512/256/128 策略"，差别只在辅助目标与更新方式：

1. 估计器（源编码器 + 目标编码器 + 原型）挂在 Actor 内部，每个 control step 前向一次，
   产出 v̂ 与 l̂；策略路径上两者 **detach**，PPO 梯度不进估计器；
2. 估计器由**自己的 Adam**、用 `L_est = MSE(v̂, 2v_{t+1})` 与 SwAV 对比损失 `L_swap` 更新，
   每个 minibatch 更新一次（5 × 4 = 20 次/轮）；
3. 对比学习的目标是**下一帧**的状态：历史 `o_{t-5..t}` 的嵌入要被拉近到
   "t+1 帧状态（去掉 command、加上 base_lin_vel）"的嵌入，跨样本的原型分配用
   Sinkhorn 生成伪标签。

所以实现上直接复用 DreamWaQ 的骨架（actor 内嵌模块、`compute_returns` 里沿时间轴移位、
观测组只增不改、ONNX 覆盖 `as_onnx`、`HimOnPolicyRunner` 的 metadata），只有估计器与
损失是新写的。

## 2. 数据流总览

```
环境每个 control step 产出（全部会被 RolloutStorage 存下来）：

  actor     (45)        当前帧本体观测（含 command），喂策略的 o_t 分支
  critic    (...)       特权观测（不变，只喂 critic）
  him_input (6 × 45)    6 帧本体观测历史 o_t..o_{t-5}，只喂源编码器
  him_state (45)        干净语义的"状态帧" = [ang_vel, gravity, joint_pos,
                        joint_vel, actions, base_lin_vel×2]，不含 command；
                        只用于目标编码器与速度标签（不入 actor / critic）

                            │
                            ▼
                RolloutStorage（按 (时间, 环境) 存全部观测组）

  ┌──────────────────── PPO update 的每个 minibatch ─────────────────────┐
  │                                                                      │
  │  him_input(270) ─→ 源编码器 270→128→64 ─┬─→ v̂ (3) ──┐                 │
  │                                          └─→ l̂ (16) ─┤                 │
  │                                                      ├─→ [o_t, v̂, l̂] = 64 │
  │  actor(45) ────────────────────────────────────────┘   → 512/256/128  │
  │                                                           → 12 维动作分布 │
  │                                                        （v̂、l̂ 在策略路径 detach）
  │                                                                      │
  │  him_state_next(45) ─→ 目标编码器 45→128→64→16 ─→ l̂_target             │
  │  him_state_next 最后 3 维 ─→ 速度真值 2v_{t+1}                          │
  │                                                                      │
  │  L_est  = MSE(v̂, 2v_{t+1})                    （done 行剔除）           │
  │  L_swap = -0.5·(q_s·log p_t + q_t·log p_s)    （prototype 16, τ=3.0,   │
  │                                                 sinkhorn ε=0.05 × 3 次） │
  │  → 估计器自己的 Adam（clip 10）                                        │
  │                                                                      │
  │  PPO：surrogate + value - entropy → 主 Adam（clip 1，只更新策略与 critic）│
  └──────────────────────────────────────────────────────────────────────┘
```

有一处必须注意：**策略在 rollout 与 update 两个时刻的 v̂、l̂ 不是同一份**（rollout 只存
观测，update 时用当前估计器重算），PPO 的重要性比里会混入估计器两次更新之间的漂移。
官方代码与 DreamWaQ 复现都是这个口径，本方案照抄，不在第一版修（见《论文未明确之处》#11）。

## 3. 环境侧：新增两个观测组（只增不改）

改动文件：`src/mjlab/tasks/himloco/himloco_env_cfg.py`、`.../config/go1/env_cfg.py`。

基座直接复用现有 Go1 rough 的 env 配置（与 DreamWaQ run 同一口径），删掉 DreamWaQ 专用的
`cenet_input` / `cenet_target_o` / `cenet_target_v` 三组，加入下面两组。**actor 组、critic 组、
奖励、地形、课程、事件、终止条件一个字不动。**

| 观测组 | 内容 | 形状 | 关键配置 |
| --- | --- | --- | --- |
| `him_input` | 与 actor 组同一份 term（含 command），带噪声 | (N, 6, 45)，展平后 270 | `history_length=6`、`flatten_history_dim=False`、`enable_corruption=True` |
| `him_state` | `[base_ang_vel, gravity, joint_pos, joint_vel, actions, base_lin_vel×2]` | (N, 45) | 单帧、`enable_corruption=True`（前 5 项噪声与 actor 组同分布，`base_lin_vel` 无噪声） |

要点：

1. **用单个 term 配 history，不要复制 6 个 term**。mjlab 的历史缓冲是"旧 → 新"
   `[o_{t-5}, ..., o_t]`，而论文/官方是"新 → 旧"；在模型里 flip 一次即可，
   口径写死不要两头都翻。
2. **目标帧必须显式构造**。官方是从特权观测里按索引切片（`[3:48]`），而 mjlab 的
   actor 组顺序与官方不同（command 在最后），所以不能照抄索引——`him_state` 用独立的
   term 列表定义：前 5 项复用 actor 组的同一份配置（含 `joint_pos` 的 `biased=True`
   与各项 clip），第 6 项 `base_lin_vel` 用 `scale=2.0`（保留官方的 ×2，见《论文未明确之处》#9）。
3. **处理顺序是 compute → noise → clip → scale**，所以 `base_lin_vel` 是"先按 ±10 m/s
   裁剪、再乘 2"，目标值域 ±20。
4. `him_state` 含**特权信息**（`base_lin_vel`），所以它绝不能进 actor 组，也不路由给
   任何网络；它只作为观测组被 storage 存下来，供估计器的损失使用。
5. `obs_groups` 里给源编码器挂一个集合，例如 `"him": ("him_input",)`；
   `him_state` 完全不挂（与 DreamWaQ 的 `cenet_target_o` / `cenet_target_v` 同理）。

## 4. 模型侧

### 4.1 `HIMEstimator(nn.Module)`（新文件 `rl/network/estimator.py`）

| 部件 | 结构 | 说明 |
| --- | --- | --- |
| 源编码器 `source` | 270 → 128 → 64 → 19（ELU） | 19 拆成 v̂(3)、l̂(16)，l̂ 过 `F.normalize` |
| 目标编码器 `target` | 45 → 128 → 64 → 16（ELU） | 输出同样 L2 归一化 |
| 原型 `proto` | `nn.Embedding(16, 16)` | 每次更新前在 `no_grad` 下原地归一化 |

对外接口（给算法与测试用）：

- `encode_history(x)` → `(v_hat, l_hat)`；
- `encode_target(state_next)` → `l_target`；
- `losses(history, state_next)` → `(est_loss, swap_loss, diagnostics)`：
  内部实现 SwAV（`p = log_softmax(score / 3.0)`，`q = sinkhorn(score)` 在 `no_grad` 下算，
  `swap = -0.5·(q_s·log p_t + q_t·log p_s).mean()`），并返回原型使用情况（诊断用）；
- 常量 `velocity_dim = 3`、`latent_dim = 16`、`input_dim = 270`、`target_dim = 45`。

sinkhorn 照抄官方实现：`Q = exp(score / 0.05).T` → 除以总和 → 交替做
"每行和 = 1/K、每列和 = 1/B" 归一化 3 次 → `(Q * B).T`。注意 **p 的温度是 3.0、
q 的 ε 是 0.05，两者不是同一个数**。

### 4.2 `HimActorModel(MLPModel)`（新文件 `rl/network/actor.py`）

继承 rsl_rl 的 `MLPModel`，动作分布 / log_prob / save-load / 优化器接线全部复用，只覆写：

| 覆写点 | 做什么 |
| --- | --- |
| `_get_latent_dim()` | 返回 `45 + 3 + 16 = 64` |
| `get_latent(obs)` | `proprio = super().get_latent(obs)`（关归一化后即原始 45 维）→ 在 `torch.no_grad()` 下跑估计器（官方 `update_distribution` 的口径）→ 缓存输出供指标用 → 返回 `cat([proprio, v, l])` |
| `as_onnx()` | 导出包装：输入 270 维历史（内部 reshape → 取最新一帧当 o_t）→ 输出 12 维确定性动作；估计器随 actor 一起导出 |

两点说明：

1. 估计器前向两次：策略路径在 `torch.no_grad()` 下前向，`HimPPO._update_estimator` 在
   自己的损失里再前向一次并保留计算图——与官方一致，PPO 的图与 HIO 的图完全分离。
   测试里断言"PPO 损失对估计器参数梯度为 0、HIO 损失不更新策略 MLP"。
2. 观测归一化关闭，因此 `update_normalization` 不需要覆写（normalizer 是 `Identity`）。

## 5. 算法侧：`HimPPO(PPO)`（新文件 `rl/algorithm/him_ppo.py`）

### 5.1 `__init__`

- `super().__init__` 之后把估计器参数从**主 optimizer** 的 `param_groups` 中剔除
  （主 Adam 只负责策略 MLP 与 critic；官方是"留在里面但永远拿不到梯度"，我们做显式剔除，
  更干净且等价）；
- 新建 `self.estimator_optimizer = Adam(estimator.parameters(), lr=learning_rate)`；
- 读取 `him_cfg`（sinkhorn 参数、梯度裁剪 10、损失权重）。

### 5.2 `compute_returns(obs)`

1. 先调 `super().compute_returns(obs)`；
2. 把 `him_state` 沿时间轴整体前移一格，最后一行用当轮最后一次 `env.step` 返回的观测补：
   `him_state_next[t] = him_state[t+1]`；
3. 写入 `him_valid = 1 - dones`。

**必须在 minibatch 打乱之前完成**（与 DreamWaQ 的重建目标同一个坑）。

### 5.3 `update()`

骨架照抄 `DreamwaqPPO.update()`（含 adaptive lr 的 KL 调整、非有限 loss/梯度保护、日志聚合、
`storage.clear()`）；RND / symmetry 分支直接报 `NotImplementedError`（本复现不用），
每个 minibatch 的顺序是：

1. 取 `observations = batch.observations`，跑一次 actor 前向（估计器在策略路径上 detach）；
2. **估计器更新**：`valid = him_valid > 0`，把 done 行整行剔除；若剩余样本 ≥ 2，
   算 `L_est`、`L_swap` → `estimator_optimizer.zero_grad()` → `backward()` →
   `clip_grad_norm_(10)` → `step()`；同时把 `param_group['lr']` 同步为 `self.learning_rate`；
3. PPO 原流程：surrogate + value - entropy → `backward()` → `clip_grad_norm_(1)` → `step()`。

done 行**整行剔除**而不是把 loss 置零，这样 Sinkhorn 的行/列归一化仍然作用在同一批样本上。
该剔除的影响已量化：稳定期每轮只有 ~0.12% 的样本（episode 长度 850~930 步），最差的
iter 0 约 5%（平均 episode 只有 20 步），之后迅速衰减；详见《论文未明确之处》#3。

### 5.4 指标与日志

| 名称 | 来源 | 说明 |
| --- | --- | --- |
| `Loss/him_est` | loss_dict | scaled MSE（v̂ 与 2v 比较） |
| `Loss/him_swap` | loss_dict | SwAV 对比损失 |
| `Loss/him_total` | loss_dict | `L_est + L_swap`，判断辅助损失与 PPO 损失的量级关系 |
| `Metrics/him_vel_error` | `extras["log"]` | 单位 m/s：`‖v̂/2 − v_{t+1}‖` 的均值，可直接与 DreamWaQ 的 `Metrics/velocity_est_error`（0.107 m/s 量级）横向比较 |
| `Metrics/him_proto_entropy` | `extras["log"]` | 批次内原型分配的归一化熵（`update()` 里累计、下一步 rollout 写出），监控"坍缩到少数原型" |
| `Metrics/him_proto_active` | `extras["log"]` | 分配质量超过 1/(2K) 的原型个数 |
| `Metrics/him_swap_accuracy` | `extras["log"]` | `argmax p_source == argmax q_target` 的比例，判断对比学习是否在学 |

`Metrics/*` 走 `extras["log"]`（rsl_rl 的 logger 会按原 key 写盘），与 DreamWaQ 的做法一致。

## 8. 与官方代码的差异（摘要）

完整清单与理由见 `论文未明确之处.md`，这里只列结论：

| 项 | 官方代码 | 本复现 |
| --- | --- | --- |

| prototype | 32 | 16（论文默认） |
| 策略前向次数 | 2 次（no_grad + 损失内） | 1 次 + detach（等价） |
| rollout 长度 | 100（论文附录写 200） | 24 |
| 奖励 / 地形 / DR / 命令 | 官方自有配置 | 沿用 mjlab（与 DreamWaQ run 同口径） |

## 9. 容易踩的坑

1. **移位时机**：`him_state → him_state_next` 必须在 `compute_returns` 里、minibatch 打乱之前
   完成；最后一行要用当轮末尾观测补，否则会少一步。
2. **done 步不能拿 reset 后的观测当 successor**：那是"新 episode 的随机初始状态"，
   属于错误监督，必须剔除（而不是把 loss 置零）。
3. **历史顺序**：mjlab 旧→新，官方新→旧，flip 一次写死。
4. **原型归一化**：原型不归一化就不是余弦相似度，SwAV 的语义会变；`p` 的温度（3.0）与
   `q` 的 sinkhorn ε（0.05）是两个独立超参。
5. **估计器必须独立优化器 + 独立裁剪**：官方 clip 10、PPO clip 1；这与 DreamWaQ 复现里
   "一个 Adam 一起吃"的口径不同，不要照 DreamWaQ 的写法抄。
6. **估计器参数不要被主 Adam 更新**：即使留在里面（官方）也依赖 detach 保证无梯度；
   我们显式剔除 param_groups，测试里断言估计器参数在 PPO step 后不变。
7. **PPO ratio 偏差**：v̂、l̂ 在 update 时重算，rollout 与 update 之间估计器已经更新过多次；
   这是官方口径，第一版不做修正（可留作后续"存 v̂/l̂ 回放"的消融）。
8. **特权信息边界**：`him_state` 含 `base_lin_vel`，绝不能进 actor 组。
9. **ONNX 导出**：必须把估计器一起导出（输入 270 维历史 → 输出 12 维动作），
   否则导出一个"没有估计器的空壳"；play 时同步关掉各组噪声。
10. **关归一化后的数值安全**：`joint_vel`（±50）、`base_ang_vel`（±30）等去掉归一化后，
    少数"物理爆炸"环境会直接给出极端样本；沿用现有 clip 与 `Episode_Metrics/peak_joint_vel`
    监控，算法侧保留非有限 loss 的跳过保护。
11. **显存/内存**：每步多存 270 + 45 维，4096 × 24 约 100 MB/轮量级，可接受。

## 10. 验证步骤

1. **静态检查**：`make check`（format + lint + type）；维度断言写进模型构造函数
   （270 / 45 / 19 / 16 / 64）。
2. **不跑仿真的单测**：
   - 前向形状：编码器 19、目标编码器 16、actor latent 64；
   - sinkhorn 性质：`q` 每行和为 `1/K`、每列和为 `1/B`，并与独立参考实现对拍；
   - 移位对齐：手工造 T=3 序列，断言 `him_state_next[t] == him_state[t+1]` 且最后一行
     来自当轮末尾观测；
   - done 剔除：把 done 行的输入置为 NaN，损失仍有限；
   - 梯度路由：PPO 损失对估计器参数梯度为 0；`L_est + L_swap` 不改变策略 MLP 参数；
   - 原型归一化：一次更新后 `proto.weight` 每行范数为 1；
   - 导出：`as_onnx()` 前向形状（输入 270 → 输出 12）。
3. **小规模冒烟**：小 env 数跑 2 次迭代，确认 `Loss/him_est`、`Loss/him_swap` 有限且
   `Metrics/him_vel_error` 在下降。
4. **正式训练**：4096 envs × 600 迭代（见下）。
5. **导出与 play**：导出 ONNX 确认输入 270 / 输出 12，并在 play 环境跑通推理。
