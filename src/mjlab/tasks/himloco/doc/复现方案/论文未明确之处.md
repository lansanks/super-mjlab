# 论文未写清、由本复现拍板的点（HIM）

> 用途：记录 HIM 论文（`paper-reading-note/himloco/2312.11460v3.pdf`）没有明确说明、
> 官方代码（`/home/linkchen/桌面/知识库/HIMLoco`，commit `ef289ac`）与论文不一致、
> 以及本复现必须选一个做法的点。这些是**实现选择**，不是论文结论。
> 相关代码：`rl/network/estimator.py`、`rl/network/actor.py`、`rl/algorithm/him_ppo.py`。

## 1. 目标编码器的输入到底取哪一帧、哪几维

**论文的说法**：目标编码器把 `o^a_{t+1}` 编码成 `l^T_t`，正文没有给出切片口径。

**官方代码**：`HIMEstimator.update` 里

```python
vel = next_critic_obs[:, num_one_step_obs : num_one_step_obs + 3]  # 特权 lin_vel
next_obs = next_critic_obs[:, 3 : num_one_step_obs + 3]  # 去掉 command、加上 lin_vel
```

在官方 45 维布局 `[cmd, ang_vel, gravity, dof_pos, dof_vel, actions]` 下，这意味着目标帧是
`[ang_vel, gravity, dof_pos, dof_vel, actions, base_lin_vel×2]`——**不含 command、含 lin_vel**，
而且速度标签取的是 **t+1 帧**的速度（不是当前帧 v_t）。

**本复现口径**：把目标帧显式定义成一个观测组 `him_state`（前 5 项与 actor 组同一份 term，
第 6 项 `base_lin_vel` 用 `scale=2.0`），目标 = 它的**下一帧**。

**原因**：mjlab 的 actor 组顺序与官方不同（command 在最后），按索引切片会取错；显式构造
观测组也顺带把"特权信息不进 actor"这条边界写进配置里。

## 2. v̂ 的语义：当前速度还是下一帧速度

**论文的说法**：正文写 "estimate the robot's velocity v̂_t"，容易被读成当前帧速度。

**官方代码**：回归标签是 `next_critic_obs` 里的 lin_vel，即**执行完 a_t 之后**那一帧的速度。

**本复现口径**：按代码，v̂ 是"系统响应"（下一帧速度）；策略在 t 时刻拿到的 v̂ 是预测值。
指标 `Metrics/him_vel_error` 也按这个口径计算（v̂ 对比 t+1 帧真值），单位换算回 m/s。

## 3. 终止步（done）的 successor 怎么处理

**论文的说法**：未提。

**官方代码**：在环境侧额外计算 `compute_termination_observations`（reset 之前的终止状态），
在 runner 里替换 `next_critic_obs[termination_ids]`，即**用终止帧当 successor**，
不 mask、不剔除。

**本复现口径（2026-10-16 拍板）**：`done = terminated | truncated` 的那些 transition
**整行剔除**，不参与 `L_est` 与 `L_swap`。

**影响量化**（用 `dreamwaq/doc/实验/实验数据/2026-10-12_14-17-48/metrics.csv` 的 episode
长度折算 done 步占比）：

| 阶段 | 平均 episode 长度 | done 步占比 |
| --- | --- | --- |
| iter 0 | 19.6 步 | ≈5% |
| iter 1 / 2 / 3~10 | 47 / 64 / 74~88 | ≈2% / 1.6% / ≈1.2% |
| iter 0–99 平均 | 590 | ≈0.17% |
| iter 100+ | 850~930 | ≈0.11% |

换成绝对数：每轮 4096 × 24 ≈ 9.8 万样本里，稳定期只有 ~110 个 done 步。结论是影响可忽略，
不值得为它做 env 侧的终止帧快照机制。**注意不能退化成"直接用 reset 后的观测当 successor"**，
那是把新 episode 的随机初始状态当作上一段历史的响应，属于错误监督，比剔除更糟。

## 4. 估计器是否接收 PPO 的梯度、用什么优化器

**论文的说法**：只说 HIO 训练 HIM、PPO 训练策略，"先更新 HIM 再冻结优化 actor/critic"；
没有说明梯度是否回传。

**官方代码**：`HIMActorCritic.update_distribution` 里估计器前向包在 `no_grad` 下，
v̂、l̂ 对策略是常数（**策略梯度不进入估计器**）；`HIMEstimator` 自己持有一个 Adam，
在 PPO 的 minibatch 循环里单独 `zero_grad → backward → clip(10) → step`，lr 跟随 PPO 当前 lr。
注意官方 PPO 的 `optim.Adam(self.actor_critic.parameters())` 其实也包含估计器参数，
但因为拿不到梯度，等价于不更新。

**本复现口径**：按官方——估计器**独立 Adam + 独立裁剪（10）**，每个 minibatch 更新一次
（5 epochs × 4 minibatches = 20 次/轮）；同时把估计器参数从主 optimizer 的 `param_groups`
里显式剔除，让"主 Adam 只更新策略与 critic"变成代码事实而不是依赖 detach。

**与 DreamWaQ 复现的口径差异（重要）**：DreamWaQ 那边 CENet 是 actor 的子模块，
辅助损失直接加进总损失、**共用同一个 Adam、同一次反传**（`dreamwaq_ppo.py` 里
`loss = ... + ce_coef*(...)`、一次 `backward()`、一次 `step()`），被"独立"的只是梯度来源。
HIM 按官方用两套优化器，因此两套复现在这一点上不可互相照抄。

## 5. 观测归一化

**论文的说法**：没有提归一化。

**官方代码**：`him_actor_critic.py` 里定义了 `Normalization` 类，但全仓库没有任何调用
（死代码），actor / critic / 估计器都吃原始观测（只做 `clip_observations = 100.` 的整体裁剪）。

**本复现口径（2026-10-16 拍板）**：关闭 `obs_normalization`（actor / critic / 估计器都不做），
与官方一致。代价是与现有那两条开着归一化的 run（velocity / DreamWaQ）不是同一口径，
因此**不做"开归一化"的对照基线**；将来若要做 A/B，对照臂必须同样关归一化。

## 6. 原型数量

**论文的说法**：正文 A.4 写"Number of prototypes 16"（按地形类型数的平方），消融章节也以
16 为默认。

**官方代码**：`HIMEstimator(num_prototype=32)`，且没有任何配置覆盖，实际跑的是 32。

**本复现口径（2026-10-16 拍板）**：先用 **16**（论文默认）；若训练中出现原型坍缩或
`Metrics/him_proto_entropy` 长期贴 0，再对照 32 做一次消融。

## 7. SwAV 的超参：温度与 sinkhorn 参数

**论文的说法**：Eq. (1) 用温度 τ 做 softmax；Eq. (2) 的目标由 Sinkhorn-Knopp 产生，
未给具体数值。

**官方代码**：`temperature = 3.0`（用于 `log_softmax(score / τ)`），
`sinkhorn(out, eps=0.05, iters=3)`（用于 `Q = exp(score / eps).T` 的传输计划）。
**两者不是同一个温度**——阅读笔记里"除以温度后上 exp 再 sinkhorn"的写法容易混。

**本复现口径**：照抄（τ=3.0、ε=0.05、3 次迭代），签名写死在 `HIMEstimator` 里，
可由 `him_cfg` 覆盖。

**官方代码**：`num_steps_per_env = 100`、`num_mini_batches = 4`（与论文附录不一致）。

以后如需"官方忠实版"再单独跑 100 步的配置。

## 9. base_lin_vel 的 ×2 缩放

**论文的说法**：未提。

**官方代码**：legged_gym 的 `obs_scales.lin_vel = 2.0`，特权观测与估计器的速度标签都是
`2 × base_lin_vel`，因此 v̂ 实际学的是"2 倍速度"，MSE 与策略输入的量级都相应地放大。

**本复现口径（2026-10-16 拍板）**：**保留 ×2**（与发布代码一致），只在指标上报时换算回
m/s（`Metrics/him_vel_error = ‖v̂/2 − v_{t+1}‖`），这样能和 DreamWaQ 的
`Metrics/velocity_est_error`（0.107 m/s 量级）直接比较。实现上就是观测 term 的
`scale=2.0`，要改成 1.0 只需动这一处。

## 10. 环境侧：奖励、地形、DR、命令

**论文的说法**：Table 5 给了一套奖励权重（与 legged_gym 的 Aliengo 配置几乎一致），
Table 6 给了一套域随机化范围，附录 A.3 给了地形生成规则。

**官方代码**与论文有若干出入：地形 5 类（论文写 4 类、比例 0.1/0.2/0.6/0.1 vs 代码
0.1/0.2/0.3/0.3/0.1）；link mass 随机化被关掉；地面摩擦上限 1.25（论文 2.75）；
payload [-1, 2]（论文 [-1, 3]）；命令重采样在代码里是 10 s（论文说每 25 步）；
奖励里限位类惩罚权重实际为 0、`base_height_target = 0.30`。

**本复现口径（2026-10-16 拍板）**：**全部沿用 mjlab 现有 Go1 rough 环境**（奖励、地形、
课程、终止、DR、命令都不动），只替换观测组。这样 HIM 与已有 DreamWaQ / velocity run
在环境侧是同一个口径，差异集中在算法与观测组。论文奖励表的移植留作后续可选项。

## 11. PPO 的重要性比里混入估计器漂移

**论文的说法**：未提。

**官方代码**：rollout 只存观测，不存 v̂、l̂；update 时用**当时的**估计器重算策略输入。
而估计器在同一轮里被更新 20 次，因此 `ratio = exp(new_log_prob − old_log_prob)` 里
既有策略的变化、也有估计器的漂移。

**本复现口径**：第一版照抄官方；作为已知偏差写在这里。
可选的后续消融：rollout 时把 v̂、l̂ 一起写进 storage、update 时原样回放
（与 DreamWaQ 给 AdaBoot 的 mask 落盘同理），代价是每步多存 19 维。

## 12. 观测噪声的实现方式

**官方代码**：actor 观测与特权观测由同一份 `current_obs` 派生，**共享同一次噪声采样**
（噪声只加在前 45 维；`command` 与 `lin_vel` 实际无噪声），所以目标帧的 proprio 部分
与 actor 当前帧的噪声是同一份实现。

**本复现**：mjlab 的观测组各自独立采样噪声（分布与范围相同，实现不同），
`him_input`、`him_state`、`actor` 三组之间噪声不共享。

**选择**：接受（与 DreamWaQ 复现的坑 #10 同一处理）。论文没有要求噪声共享同一实现；
若将来发现对训练有影响，再考虑让这些组共享噪声实例。
