# 论文未写清、由复现自行拍板的点

> 用途：记录 DreamWaQ 论文（`doc/dreamwaq.pdf`）没有明确说明、而我们复现时必须选一个做法的点。
> 这些是**实现选择**，不是论文结论；以后回看时不要拿它们当作论文的依据。
> 相关代码：`rl/network/cenet.py`、`rl/network/actor.py`、`rl/algorithm/dreamwaq_ppo.py`。

## 1. CENet 是否接收 PPO 的反向传播

**论文的说法**：只写了 "CENet is optimized using a hybrid loss function
`L_CE = L_est + L_VAE`"（II-C）、"synchronously train the policy, value, and CENet
networks"（III-B）。没有任何公式或文字说明 v̂、z 送进策略之前是否 detach，
也就是"策略梯度是否回传到 CENet 编码器"。

**我们的选择（2026-10-12 起）**：detach（stop-gradient）。actor 路径上的 v̂、z 一律加
`.detach()`（`DreamwaqActorModel.get_latent`），PPO 损失对 CENet 参数的梯度严格为零；
CENet 只由辅助损失 `L_CE = L_est + L_recon + β·KL` 更新。`L_CE` 与 PPO 损失仍在同一
次 backward、同一个 Adam 里更新（"同步训练"的单阶段流程不变），缓存给辅助损失的
`_last_cenet_output` 保留计算图。

历史：`4dfa594e0`（2026-10-12 13:52）之前的 run 都是**不 detach 的耦合版本**（v̂、z
直接进策略、策略梯度回传编码器）；该提交之后改为 detach 版，用于两版对照实验。

**原因**：

1. 论文的表述指向同一方向：II-C 把 CENet 的优化目标写成 `L_CE` 本身；Fig.2 图注
   "the shared encoder is trained to provide a robust body state and context
   estimation jointly"；Fig.1 的 "Policy gradient" 虚线只连接 Actor 与 Critic、
   不进 CENet；III-E 把估计精度归因于 VAE 自编码与"前向-后向动力学学习"。III-B 的
   "synchronously train" 讲的是训练日程（单阶段、非 teacher-student 两段式），detach 下
   三个网络仍在同一循环、同一个 Adam 里同步更新，同样满足。
2. v̂ 有真值监督（`L_est`），又是 AdaBoot 里"需要被鲁棒对待的估计"，必须保持为诚实的
   估计量。若策略梯度能改 v̂，它会被塑形成"策略喜欢的输入特征"，污染 `L_est`、
   `Metrics/velocity_est_error`、`est_vel_mean_pct` 的口径与 AdaBoot 的前提。
3. z 由重建 + KL 定义；策略梯度进 z 等于开一条不受 KL 约束的通道，β 的"信息预算"语义
   会变糊。
4. 本复现的 β 扫描、KL/recon 判据、latent drift/spread 判读都建立在"CENet 只被 `L_CE`
   塑形"的假设上，detach 后这套口径更干净。

**代价**（如实记录）：encoder 失去"为策略回报塑形特征"的能力，z 只能靠重建任务自己长出
地形 context，策略侧靠 MLP + AdaBoot 消化估计误差；论文对 z/v̂ 的定位本就是估计量，
代价可接受。

## 2. 策略输入的 z_t 用采样还是后验均值

**论文的说法**：Fig.2 画出 `z_t` 从后验 `q(z_t | o_t^H)` 采样，但正文没有说明
喂给策略的是采样值还是均值。

**我们的选择**：策略路径固定用后验均值 μ（`CENet(..., sample=False)`，见
`DreamwaqActorModel.get_latent`）；VAE 的重建项 `L_recon` 仍然每次从后验采样 z
（`CENet.reparameterize`）。推理 / ONNX 导出同样用 μ。

**原因**：策略输入保持确定性，PPO 的重要性比才严格成立——否则 rollout 时采样的 z 和
update 重算时重新采样的 z 不是同一个，ratio 里会混进与策略更新无关的噪声；
同时训练与部署（ONNX 输入）口径一致。

> 如果以后要改成"策略也吃采样 z"：rollout 时记录 ε = (z − μ) / σ，`compute_returns`
> 里注入 `cenet_eps`，actor 的 `get_latent` 在 obs 含该 key 时改用 `z = μ + σ·ε`。

## 3. AdaBoot 的实现口径

**论文的说法**：`p_boot = 1 − tanh(CV(R))`（Eq. 8），`CV(R) = std(R) / mean(R)`，
R 是"m 个域随机化环境"的 episodic reward 向量，**每个 learning iteration** 算一次。
早期 CV 大 → p_boot 小 → 不用估计值（用真值 v_t 稳住训练）；学好后 CV 小 → p_boot 大
→ 用 v̂（bootstrap），练出对估计误差的鲁棒性。论文没说：R 具体取哪一段回报、掷骰子的
粒度、以及"自举"到底替换哪些量。

**我们的选择**（对应 `DreamwaqPPO` 的 `dreamwaq_cfg={"adaboot": True,
"boot_granularity": "env"}`）：

1. **R 的口径**：每个环境"最近一次已完成 episode 的 undiscounted return"滚动向量，
   m = 至少完成过一次 episode 的环境数。有效样本 < 2（CV 无定义）或 mean ≤ 0
   （视为还没学好）时 p_boot = 0。std 用 `torch.std` 默认的样本标准差，分母取 |mean|
   并 clamp 兜底，最后把 p_boot 截断到 [0, 1]。
2. **掷骰粒度**：`boot_granularity="env"`——每个环境每次 rollout 独立掷一次，
   环境内 24 步保持一致，环境之间混合；一个 minibatch 里用 v̂ 的样本比例 ≈ p_boot。
   可选 `"iteration"`（整轮一次骰子、全部环境一致），更贴论文"per learning iteration"
   的字面措辞。
3. **替换范围**：只替换 actor 输入里的 3 维速度槽
   `v = flag · v̂ + (1 − flag) · v_t`；z 恒用 μ（没有真值可换）。`L_est`、重建目标、
   critic 观测（含 d_t）都不受影响。
4. **时间线**：首轮 p_boot = 0；每轮 rollout 结束后用本轮结算的 episode return 更新
   p_boot，作用于**下一轮** rollout（因果上无法提前知道本轮回报）。
5. **mask 必须落盘**：每步的 flag 写进 rollout storage（key `cenet_boot_flag`），
   update 重算 log-prob 时原样复用。否则 rollout 与 update 的 actor 输入不一致，
   PPO 的重要性比会被污染。这是论文没提、但实现上必须做的一步。
   （如果将来开启 rsl_rl 的 symmetry 数据增强，它的 `data_augmentation_func`
   需要一起搬运这个 key。）
6. **部署/推理**：ONNX 与 play 没有 `cenet_boot_flag`，恒用 v̂（部署时本来也没有真值）。
7. **状态持久化**：p_boot、每环境 episode 累计回报、最近一次回报、是否已有回报标记
   写进 checkpoint（`adaboot_state_dict`）；加载旧 checkpoint 时打印警告并从 p_boot = 0 重来。

**原因**：粒度取 per-env-per-rollout 是中道选择——环境内输入来源不跳变（避免 50 Hz 抖动），
环境间混合让每个 minibatch 里都有约 p_boot 比例的样本用 v̂、其余用真值，策略在两种
输入下都得到训练；只换 v 是因为 z 没有真值可换；mask 落盘是 PPO ratio 正确性的硬性要求。

## 4. 其他已知留白（备忘，暂按默认值实现）

- **β（KL 权重）**：论文没给。**2026-10-12 定为 β = 0.045，目标收敛 KL ≈ 5 nat**
  （16 维合计，≈0.31 nat/维）。标定数据与推导见《实验记录.md》第 8 节，要点：
  存活区（β∈[0.03, 0.12]）实测 `β·KL ≈ 0.23 ± 0.03`（反比），故
  `β ≈ 0.23 / KL_target`；由 KL = ½Σ(E[μ²] + E[σ²−1−lnσ²]) ≥ ½ΣE[μ²] 得
  **‖μ‖ ≤ √(2·KL)**——KL=5 时 ‖μ‖ ≤ 3.2，落在 16 维 N(0,I) 的典型半径（4.0）
  以内，先验采样/插值仍有意义、每维偏离与归一化观测同量级（O(1)）。
  上限 KL ≲ 8（‖μ‖ ≤ 4.0）；坍缩实测在 KL≈0.005（β≥0.2）；率失真拐点同在
  4~6（45 维解释率 42%→49%→71.5% 对应 KL 2.4→5.2→139）；策略指标与压力测试
  对 β 不敏感（detach 三个 β 打平），不构成反对。已验证：β=0.04
  （`2026-10-12_16-06-44`）实测收敛 KL≈5.2，已落在目标上。
- **L_CE 相对 PPO 损失的权重**：论文没给，固定 `ce_coef = 1.0`
  （`Loss/cenet_total` 已在日志里，可直接看它与 surrogate/value 的量级关系）。
- **观测归一化的实现方式**：论文只说"所有观测归一化到零均值、单位方差"，没说用什么统计方式。
  我们用的是 running 统计量的 `EmpiricalNormalization`：actor 观测一份、CENet 历史按 45 维一份。
- **论文 Fig.2 的 48 维**：与 Eq.(1) 的 45 维矛盾，按笔误处理；重建目标用 45 维
  （与本地 actor 观测一致）。
- **观测 clip**：论文没提（仿真与真机的数值安全是工程细节）。我们对可能"物理爆炸"的
  观测项加了硬上限：`joint_vel` ±50、`base_ang_vel` ±30、`actions` ±20、`joint_pos` ±3、
  critic 的 `base_lin_vel` ±10。目的是把"少数环境仿真失控"的伤害隔离在少量样本内
  （否则单个极端样本能一次更新打死策略，见《实验记录.md》806 轮复盘）。
  部署端要用同一套 clip —— ONNX metadata 里 `observation_terms_clip` 已记录这些范围。
