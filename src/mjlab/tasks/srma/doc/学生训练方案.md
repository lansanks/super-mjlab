# SRMA 学生阶段训练与代码实现方案

## 0. 文档目的

本文是 SRMA 学生阶段从方案讨论转入代码实现时的交接文档。目标是让新的实现会话
不需要依赖此前对话，即可直接完成代码、测试和首轮训练验证。

当前教师阶段训练结果已经足以作为冻结特权教师。学生阶段第一版采用：

```text
冻结教师
  -> 估计器预热
  -> 教师/学生混合行为的在线 DAgger
  -> 学生占 80%、教师保留 20% 的长期混合训练
```

第一版不加入 PPO，不使用环境奖励更新学生参数。奖励、终止和地形课程仍然保留，
用于环境推进、日志、评测和 episode 管理。

第一版已经确定的关键口径：

- 估计器预热 20 轮，预热期间教师比例为 100%；
- rollout、教师监督标签和部署都使用确定性动作均值；
- 动作损失使用归一化均值 MSE，不计算或记录动作 KL；
- 教师比例按最大轮数每 10% 降低 10 个百分点，最低保留 20%；
- 不使用自动守门评测，教师比例只按轮次调度；
- 第一版只支持单卡训练；
- 教师 checkpoint 固定为
  `logs/rsl_rl/go1_srma_teacher/2026-10-19_14-32-41/model_3999.pt`。

本文描述的是当前确定的目标设计。实现时应先检查工作区已有改动，不能覆盖用户尚未
提交的教师奖励、终止或实验记录修改。

## 1. 当前教师基础

教师策略由两部分组成：

```text
特权外部观测 e_t
  -> SRMAExternalEncoder
  -> l_teacher(16)

[actor_obs(45), v_gt(3), l_teacher(16)]
  -> teacher actor MLP
  -> action(12)
```

教师外部编码器和教师 actor 都属于完整教师策略，训练学生时全部冻结。

当前教师 checkpoint 的主要结构如下：

```text
actor_state_dict
  obs_normalizer.*
  distribution.std_param       (12,)
  mlp.0.weight                 (512, 64)
  mlp.6.weight                 (12, 128)
  external_encoder.*
```

教师 actor 和学生 actor 的输入维度都是 64，因此学生 actor 可以由教师 actor 初始化。
学生实现会复制 `distribution.std_param` 以保持模型结构兼容，但学生训练和 rollout
都不使用该标准差：行为动作和动作标签都直接使用确定性均值。

现有教师实现参考：

```text
src/mjlab/tasks/srma/rl/network/teacher_actor.py
src/mjlab/tasks/srma/rl/network/external_encoder.py
src/mjlab/tasks/srma/rl/algorithm/teacher_ppo.py
src/mjlab/tasks/srma/config/go1/rl_cfg.py
```

## 2. 核心设计决策

### 2.1 教师和学生各自的职责

教师负责两件事：

1. 根据外部特权信息生成 `l_teacher`；
2. 根据 `[actor_obs, v_gt, l_teacher]` 生成动作标签。

学生只使用部署可获得的 45 维本体观测：

```text
o_t(45)
  -> GRU(hidden=64)
  -> v_hat(3)
  -> l_hat(16)

[normalized o_t(45), v_hat(3), l_hat(16)]
  -> student actor MLP
  -> action(12)
```

学生不能读取高度图、摩擦、外力、contact 或 air time。

### 2.2 教师控制与学生控制的区别

教师控制环境时，执行完整教师策略：

```text
l_teacher = Enc_T(e_t)
a_teacher_mean = mean(pi_T(o_t, v_gt, l_teacher))
a_behavior = a_teacher_mean
```

学生控制环境时，执行学生策略：

```text
v_hat, l_hat = GRU(o_t, h_{t-1})
a_student_mean = mean(pi_S(o_t, v_hat, l_hat))
a_behavior = a_student_mean
```

无论谁控制环境，教师都会在当前状态上重新生成标签：

```text
v_gt
l_teacher
a_teacher_mean
```

教师控制环境的作用是：

- 避免学生早期能力不足导致大量环境立即失败；
- 提供稳定、高质量的专家状态；
- 帮助学生接触更高地形课程等级；
- 降低早期 rollout 方差；
- 让估计器先覆盖更丰富的稳定状态。

教师控制轨迹不是最终的 DAgger 纠错信号。真正的 DAgger 信号来自学生控制环境后访问到
的状态，以及教师在这些状态上的纠正标签。

### 2.3 行为策略比例

设学生阶段最大轮数为 `max_iterations`，当前绝对轮次为 `iteration`，教师目标比例为
`teacher_fraction`。默认 `teacher_fraction_start=1.0`、
`teacher_fraction_min=0.2`：

```text
decile = floor(10 * iteration / max_iterations)
teacher_fraction = max(
    teacher_fraction_min,
    teacher_fraction_start - 0.10 * decile,
)
```

比例按轮数分段阶跃下降，不做线性插值。以 `max_iterations=500` 为例：

| 轮次 | 教师比例 | 学生比例 |
| --- | ---: | ---: |
| 0–49 | 1.00 | 0.00 |
| 50–99 | 0.90 | 0.10 |
| 100–149 | 0.80 | 0.20 |
| 150–199 | 0.70 | 0.30 |
| 200–249 | 0.60 | 0.40 |
| 250–299 | 0.50 | 0.50 |
| 300–349 | 0.40 | 0.60 |
| 350–399 | 0.30 | 0.70 |
| 400 以后 | 0.20 | 0.80 |

不需要逐层解冻 actor。DAgger 开始时 actor 的所有层直接训练；逐渐变化的是教师控制
环境的比例，而不是 actor 各层的可训练状态。

比例分配必须在 episode reset 时完成：

```text
以概率 teacher_fraction 将该 episode 分配给教师
以概率 1 - teacher_fraction 将该 episode 分配给当前学生
```

角色保持到 episode done，不能在每一步随机切换。

由于角色按 episode 保持，阶段边界处的实际教师比例会短暂滞后于目标比例。实现应记录
实际教师比例，但不得为了对齐目标比例而中途强制切换角色。

### 2.4 教师比例不使用守门条件

第一版以及后续主训练流程都不使用闭环胜负、latent rank 或动作误差来决定教师比例。
教师比例只由轮次调度决定，避免训练过程中的评测扰动 RNG、课程状态和 recurrent hidden
state。指标仅用于日志和训练后分析。

### 2.5 Loss 的梯度路径

第一版采用：

```text
velocity_for_actor = v_hat.detach()
latent_for_actor = l_hat.detach()
```

估计器预热阶段：

```text
L_estimator = lambda_v * L_v + lambda_l * L_l
```

只更新：

- student GRU；
- `v_hat` 输出头；
- `l_hat` 输出头。

DAgger 阶段：

```text
L = lambda_v * L_v
  + lambda_l * L_l
  + lambda_a * L_a
```

梯度归属如下：

```text
L_v -> GRU + velocity head
L_l -> GRU + latent head
L_a -> student actor only
```

不要让 `L_a` 通过学生 actor 的估计值输入反传到 GRU。后续可以把“允许低权重
action gradient 进入 estimator”作为消融，但不能放进第一版主方法。

## 3. 损失定义

速度误差按 3 个维度分别归一化：

```text
L_v = mean(((v_hat - v_gt) / sigma_v)^2)
```

`sigma_v` 的形状为 `(3,)`，`sigma_v` 使用教师速度目标的 running scale，
`clamp_min=0.1`。

latent 误差：

```text
L_l = mean((l_hat - l_teacher)^2)
```

教师 latent 和学生 latent 都已经经过 LayerNorm。

动作误差按 12 个动作维度分别归一化：

```text
L_a = mean(((a_student_mean - a_teacher_mean) / sigma_a)^2)
```

`sigma_a` 的形状为 `(12,)`，使用教师动作的 running scale，`clamp_min=0.05`。
`sigma_a` 是动作标签的归一化尺度，不是策略动作分布的 `std_param`。

教师动作目标、教师行为动作和学生行为动作全部使用动作均值：

```text
a_teacher_mean = mean(pi_T)
a_student_mean = mean(pi_S)
a_behavior = a_teacher_mean 或 a_student_mean
```

不能使用教师 rollout 中随机采样的单次动作作为回归目标，也不从学生分布中采样执行
动作。

教师动作、教师 latent 和 `v_gt` 全部使用 stop-gradient。

第一版不使用 KL、NLL、动作方差损失或动作熵损失。学生 checkpoint 中的
`distribution.std_param` 仅用于结构兼容，不参与训练决策。

确定性均值并不等同于放弃泛化。教师动作分布是状态无关的单峰高斯，其标准差来自 PPO
探索项，并不表示当前地形或摩擦的不确定性。第一版的泛化主要来自学生控制状态覆盖、
长期保留的教师 episode、教师在学生状态上的纠正标签，以及现有观测噪声、动力学随机化
和地形/命令课程。后续若出现动作均值误差低但闭环失败，再单独验证动作扰动或 KL，
不把训练动作分布的方差混入第一版。

初始权重：

```text
lambda_v = 1.0
lambda_l = 1.0
lambda_a = 1.0
```

## 4. 第二阶段完整训练流程

### 4.1 初始化

1. 创建训练环境，保留教师传感器和教师观测组。
2. 实例化教师 actor 和外部编码器。
3. 从教师 checkpoint 加载教师参数。
4. 将教师设置为 `eval()`，并把所有参数设为 `requires_grad=False`。
5. 创建学生 GRU 和学生 actor。
6. 从教师 state dict 复制：

```text
mlp.*
obs_normalizer.*
distribution.std_param
```

7. 学生 GRU、`v_hat` 输出头和 `l_hat` 输出头随机初始化。
8. 初始化每个环境的学生 hidden state。

### 4.2 估计器预热

默认预热 20 个 learning iteration。

每一步：

1. 教师控制环境。
2. 教师编码器生成 `l_teacher`。
3. 教师 actor 输出确定性动作均值并推进环境。
4. 学生 GRU 仍然对当前 `o_t` 做前向。
5. 计算 `L_v` 和 `L_l`。
6. 只更新估计器参数。

学生 actor 在此阶段不参与 rollout，也不接收 actor loss。

预热的结束条件可以配置为固定轮数。后续若加入验证集，可提前停止，但第一版先保持
固定轮数，便于复现实验。

### 4.3 混合行为 DAgger

进入 DAgger 后：

1. actor 整体恢复可训练。
2. 每个 episode reset 时按当前 `teacher_fraction` 分配教师或学生行为。
3. 每一个时间步都运行学生 GRU 和学生 actor 前向。
4. 每一个时间步都运行冻结教师生成标签。
5. 实际执行动作由当前 episode 的行为角色决定，且教师和学生都执行确定性动作均值。
6. 按时间顺序保存 transition。
7. episode done 时清零对应环境的学生 hidden。
8. done 环境在下一次 reset 时重新采样行为角色。

教师控制的 transition 也要训练学生 actor。虽然学生动作没有被执行，但学生 actor
仍然要学习在这些专家状态上输出教师动作均值。

### 4.4 长期 80/20 混合阶段

当轮次达到最大轮数的 80% 后，教师比例稳定在 20%：

1. 新 reset 的 episode 中约 80% 由学生控制、20% 由教师控制；
2. 教师控制的 episode 继续提供稳定状态和高课程等级覆盖；
3. 教师仍然在全部状态上生成 `v_gt`、`l_teacher` 和动作均值标签；
4. 学生 GRU 和 actor 继续联合训练，直到达到 `max_iterations`；
5. 学生闭环能力通过固定评测脚本或固定 seed 实验单独验证，不嵌入训练循环。

教师比例不会降到 0，也不存在“学生完全接管”的训练阶段。

### 4.5 第一版不做 PPO

第一版学生训练不使用 reward、return、advantage、PPO ratio 或 critic。

环境奖励仍可保留，原因如下：

- 用于控制台和 TensorBoard/W&B 日志；
- 用于固定地形闭环评测；
- 用于后续单独 PPO 微调阶段；
- 终止条件和卡住 reset 仍影响 episode 和 hidden 管理。

如果纯 DAgger 后出现“动作误差已低但闭环明显落后教师”，再另开阶段加入 PPO，
不能在第一版同时混入 PPO。

## 5. 序列与 hidden state 设计

第一版参数：

```text
num_steps_per_env = 50
sequence_length = 50
gru_hidden_dim = 64
gru_num_layers = 1
```

一次 update 可以按环境划 mini-batch，但每个环境内部必须保留完整时间顺序。

不要随机打乱单步 transition。可以打乱环境索引，然后在每个环境子集上从初始 hidden
展开全部 50 步。

在序列内遇到 done 时，当前步仍参与损失；从下一步开始将对应环境的 hidden 清零。

第一版先做完整 50 步反传，不先截断为 25 步。若显存或速度不可接受，优先减小环境
mini-batch，再考虑 TBPTT。

### 5.1 为什么需要保存初始 hidden

rollout 可能从 episode 中间开始，学生 hidden 不是零。为了在 update 时按新参数
重新展开序列，storage 必须保存 rollout 开始时的：

```text
initial_hidden: [num_layers, num_envs, hidden_dim]
```

更新阶段使用局部 hidden 计算，不修改 rollout 使用的持久 hidden。

### 5.2 关于 RSL-RL `Distillation`

当前安装版本是 RSL-RL 5.5.1。不要把自带 `Distillation` 直接当作主实现：

- 它只执行 student action；
- 它只计算学生/教师动作 MSE；
- 它不处理本方案需要的行为比例；
- 它没有直接实现 `L_v/L_l/L_a` 的分流；
- 它的 `gradient_length` 是累计多少步做一次优化，不应被误解为独立序列长度；
- 它的通用 storage 会复制全部观测组，对教师高度图和 critic 观测造成不必要的显存占用。

可以阅读其实现作为参考，但 SRMA 学生阶段应使用自己的 storage 和 algorithm。

## 7. 学生环境配置

### 7.1 函数接口

### 7.2 训练环境

保留所有教师观测组和教师传感器：

```text

teacher_friction
teacher_prev_push
teacher_velocity_gt
```

```text

teacher_friction
teacher_prev_push
```

删除顺序应为：

1. 删除教师观测组；
2. 删除不再被引用的教师传感器；
3. 保留奖励、终止、地形和其他 play 所需传感器。

必须确保 ObservationManager 不再引用被删除的传感器。

## 8. 学生网络实现

### 8.1 类与配置

在 `student_actor.py` 中实现：

```python
class SRMAStudentActorModel(MLPModel): ...
```

模型配置键建议：

```text
obs_group

gru_num_layers
```

## 9. 自定义 Storage

### 9.1 目的


只存储学生训练所需的观测和标签，避免复制教师高度图、critic 和完整环境观测。

### 9.2 数据字段

```text
obs_actor          [T, B, 45]
teacher_action     [T, B, 12]
teacher_velocity   [T, B, 3]
teacher_latent     [T, B, 16]
behavior_action    [T, B, 12]
is_teacher         [T, B, 1]
dones              [T, B, 1]
initial_hidden     [layers, B, 64]
```

其中 `teacher_action` 是教师动作均值，`behavior_action` 是实际执行的确定性动作均值。

建议额外记录但不参与损失：

```text
rewards            [T, B, 1]
```

主要用于采样和调试。

### 9.3 Storage 接口

```python
set_initial_hidden(hidden)
add_transition(transition)
clear()
env_mini_batches(num_mini_batches)
```

`env_mini_batches` 只能沿环境维切分，不能打乱时间维。

## 10. 自定义 DAgger 算法

### 10.1 类接口

在 `student_dagger.py` 中实现：

```python
class SRMAStudentDagger: ...
```

必须兼容当前 `OnPolicyRunner` 的调用链：

```text
act
process_env_step
compute_returns
update
train_mode
eval_mode
save
load
get_policy
```

还需要提供 runner 日志读取的：

```text
learning_rate
```

### 10.2 `act`

伪代码：

```python
with torch.no_grad():
  teacher.get_latent(obs)
  teacher_latent = teacher.last_external_output.latent
  teacher_action_mean = teacher.action_mean_with_latent(obs, teacher_latent)

student_estimates = student.update_estimator(obs)
student_action_mean = student.actor_mean(
  obs,
  student_estimates.velocity.detach(),
  student_estimates.latent.detach(),
)

action = where(is_teacher, teacher_action_mean, student_action_mean)
```

实现时应避免重复执行教师外部编码器。不从教师或学生的动作分布中采样。

### 10.3 行为角色

算法维护：

```text
behavior_is_teacher: [B, 1]
```

初始化：

- 预热阶段全部为 `True`；
- DAgger 阶段按当前 `teacher_fraction` 采样；
- done 环境重新采样。

`teacher_fraction` 必须位于 `[0.2, 1.0]`，第一版不会降到 0。

### 10.4 `process_env_step`

必须完成：

```text
存储 transition
student.reset(dones)
对 done 环境重新采样行为角色
记录实际教师比例
```

### 10.5 `update`

阶段选择：

```text
iteration < pretrain_iterations:
  估计器预热
else:
  混合行为 DAgger
```

预热阶段：

```text
actor.requires_grad_(False)
计算 L_v + lambda_l * L_l
只优化 estimator parameters
```

DAgger 阶段：

```text
actor.requires_grad_(True)
计算 L_v + lambda_l * L_l + lambda_a * L_a
优化全部 student parameters
```

教师参数从不加入 optimizer，也始终保持 eval。

### 10.6 教师比例调度

调度使用学生阶段的绝对轮次，不使用 actor loss 或闭环评测结果：

```text
decile = floor(10 * iteration / max_iterations)
teacher_fraction = max(
    teacher_fraction_min,
    teacher_fraction_start - 0.10 * decile,
)
```

其中 `iteration` 是学生训练的总轮次，`max_iterations` 是配置中的学生训练总预算。
前 20 轮估计器预热同样包含在轮次预算内，并保持教师比例 1.0。轮次达到最大轮数的
80% 后，教师比例固定为 0.20。

当前 episode 的行为角色不因阶段边界而强制切换。日志中的实际教师比例使用当前
`behavior_is_teacher` 统计，预期会围绕目标比例短期波动。

### 10.7 Metrics

建议记录：

```text
Loss/student_velocity
Loss/student_latent
Loss/student_action
Metrics/student_teacher_fraction
Metrics/student_velocity_error
Metrics/student_latent_mse
Metrics/student_action_mse
Metrics/student_latent_std
Metrics/student_latent_effective_rank
Metrics/student_action_delta_zero
Metrics/student_action_delta_shuffle
```

latent 干预指标可以每 N 次 update 计算，避免每轮运行大 batch 的 Eigen 分解。
这些指标只用于分析和训练后报告，不参与比例调度。

## 11. Runner 设计

### 11.1 类

在 `runner.py` 中实现：

```python
class SRMAStudentRunner(MjlabOnPolicyRunner): ...
```

第一版只支持单卡训练。如果检测到 `WORLD_SIZE > 1`，必须直接报错，避免各进程独立
更新学生参数后发生不可见分叉。多 GPU 的学生梯度同步不在第一版范围内。

### 11.2 训练模式

训练环境包含教师观测组时：

1. 构造教师和学生；
2. 从
   `logs/rsl_rl/go1_srma_teacher/2026-10-19_14-32-41/model_3999.pt`
   加载教师；
3. 冻结教师；
4. 将教师 actor 复制到学生 actor；
5. 构造自定义 DAgger 算法；
6. 允许训练脚本随后加载学生 checkpoint 恢复训练。

### 11.3 Play 模式

Play 环境没有教师观测组时：

1. 只构造学生；
2. 不要求 `teacher_checkpoint`；
3. `get_inference_policy()` 返回学生；
4. 绑定 `env.srma_velocity_estimate` 供可视化；
5. 只导出学生 ONNX。

### 11.4 `load_cfg` 兼容

现有 `play.py` 会调用：

```python
runner.load(
  path,
  load_cfg={"actor": True},
  strict=True,
  map_location=device,
)
```

自定义算法必须把 `{"actor": True}` 解释为学生 actor/student：

- play 时加载 `student_state_dict`；
- 不能尝试严格加载教师权重到 play 环境的学生模型；
- 学生 checkpoint 内部的 teacher state 可以忽略。

### 11.5 Checkpoint

学生 checkpoint 至少包含：

```text
student_state_dict
teacher_state_dict
optimizer_state_dict
iter
infos
  env_state
  srma
    pretrain_iterations
    schedule_max_iterations
    schedule_decile
    actual_dagger_round
    teacher_fraction
    teacher_checkpoint
```

加载规则：

| checkpoint 类型 | 行为 |
| --- | --- |
| 教师 checkpoint | 加载教师，初始化学生 actor |
| 新学生训练 | 从 `teacher_checkpoint` 加载教师 |
| 恢复学生训练 | 加载学生、优化器和阶段状态 |
| play | 只加载学生 state |

必须检查恢复训练时的教师模型配置和 checkpoint key 是否一致。
恢复时必须保留原始 `schedule_max_iterations`，否则同一个学生 checkpoint 在不同 CLI
预算下会得到不同的教师比例。

## 15. 首轮实验验收标准

代码跑通不等于方法有效。第一轮训练至少检查：

1. 预热后 `v_hat` 误差稳定下降，且不出现 NaN；
2. `l_hat` 不是常数，有效秩大于 2；
3. `L_a` 在 DAgger 前段持续下降；
4. 学生控制环境比例提高后，终止率没有持续失控；
5. 学生比例达到 80% 后，学生能在固定 terrain level 3/5 闭环运行；
6. 学生 latent 置零或打乱后，动作和闭环性能明显下降；
7. student play 只依赖 45 维本体观测和一个 64 维 hidden state；
8. ONNX 能在无教师编码器的情况下完成推理；
9. 固定 20 cm 台阶上与教师行为做定量对照；
10. 训练曲线之外，至少保留一组固定 seed 的闭环数据。

如果学生动作误差下降但 latent 置零没有任何影响，说明 actor 忽略了 `l_hat`，不能只
根据 loss 判断方法成功。

## 16. 已知风险和待验证问题

### 16.1 教师前瞻信息不可观测

教师局部高度图包含机身前方区域，学生只能依赖历史。教师可能在首次接触障碍前就产生
anticipatory action，而学生无法从当前和过去本体观测中准确推断该信息。

需要分析：

- `l_hat` 相对 `l_teacher` 是否固定滞后；
- 接触事件前后 latent 变化时间；
- 第一级台阶成功率；
- 教师控制与学生控制轨迹的 latent 误差差异。

如果该问题严重，可以考虑缩小教师高度图前瞻范围或训练因果教师，但不能通过简单提高
`L_l` 权重解决。

### 16.2 Latent 塌缩

学生 actor 可能只依赖 `o_t/v_hat`，忽略 `l_hat`。必须监控：

- latent 每维方差；
- effective rank；
- zero/shuffle intervention；
- 不同地形上的 latent 分布。

### 16.3 纯 DAgger 的累计误差

如果学生动作误差已经较低但学生控制后仍明显失败，说明行为分布仍然存在缺口。优先：

1. 延长学生占 80% 的长期混合阶段；
2. 增加学生状态上的训练；
3. 检查教师前瞻问题；
4. 最后才考虑独立 PPO 微调。

### 16.4 历史数据聚合

第一版只保存当前 rollout，属于 online DAgger 变体，不做完整历史 dataset
aggregation。长期保留 20% 教师 episode 用于补充稳定状态和恢复状态。若论文需要严格
宣称标准 DAgger，后续仍应增加历史序列缓冲区，并保证：

- 序列按时间保存；
- hidden 起点正确；
- done 边界正确；
- 旧策略数据比例可控。

## 17. 明确不做的事情

第一版实现中不要加入：

- PPO；
- critic；
- reward-driven actor loss；
- 动作 KL、NLL、方差损失或熵损失；
- 从教师或学生动作分布中采样 rollout 动作；
- 自动守门评测或由评测结果暂停比例调度；
- 多 GPU 学生训练；
- VAE 重建；
- AdaBoot；
- 逐层解冻 actor；
- 每步随机切换教师和学生；
- 混用 RSL-RL `Distillation.update`；
- 在 play 环境创建教师传感器；
- 在 actor ONNX 中依赖教师编码器。
